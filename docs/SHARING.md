# 공유 모드 설계

여러 휴대폰(Android·iOS 섞여도 됨)이 같은 집의 일정을 보고 고칠 수 있게 합니다. 2026-11-06 소유자 결정으로 첫 출시에 포함합니다(D-090). 조사 근거는 [DECISIONS.md](DECISIONS.md) 근거 자료에 있습니다.

## 원칙

- **로컬 우선은 그대로입니다.** 화면은 계속 기기 안의 SQLite만 읽습니다. 서버는 변경을 주고받는 통로이며, 서버가 멈추거나 오프라인이어도 앱은 동작합니다.
- **공유는 선택입니다.** 켜기 전에는 아무것도 보내지 않습니다. 켤 때 보낼 내용, 저장 위치, 보관 기간을 보여 주고 동의를 받습니다.
- **보내는 것은 최소한입니다.** 집 이름, 구성원 별칭·그림·색·비율, 집안일, 일정, 완료 기록만 보냅니다. 기기 설정, 알림 설정, 알림함은 기기에 남깁니다.
- **덮어쓰지 않습니다.** 행마다 서버 버전을 두고, 다른 기기가 먼저 바꾼 행은 서버 값을 따르며 사용자에게 알립니다.

## 계정: 익명 로그인 + 초대 코드

| 선택지 | 판단 |
|---|---|
| 익명 로그인 (채택) | 이메일·비밀번호를 받지 않음. Apple 4.8(소셜 로그인 시 Apple 로그인 필수) 해당 없음. 메일 발송 서버 불필요(Supabase 기본 SMTP는 시간당 2통, 운영 불가) |
| 이메일 OTP | 복구는 쉽지만 자체 SMTP와 도메인이 필요하고 이메일을 수집하게 됨 |
| Google·카카오 | Apple 로그인을 함께 넣어야 하고 수집 항목이 늘어남 |

익명 계정의 한계는 앱을 지우거나 휴대폰을 바꾸면 그 기기의 계정에 다시 들어갈 수 없다는 점입니다. 그래서 집에 남은 다른 구성원이 초대 코드를 다시 보내면 들어올 수 있게 합니다. 혼자 남은 경우에는 로컬 백업 파일로 복구합니다. 이 한계는 공유 시작 화면에서 안내합니다.

## 초대

- 코드는 128비트 난수를 Crockford Base32 26자로 만들고 4자씩 끊어 보여 줍니다. 메시지로 보내기와 직접 입력을 모두 지원합니다.
- 서버에는 SHA-256 해시만 저장합니다. 유효 기간은 7일, 최대 사용은 5회이며, 관리자는 언제든 폐기할 수 있습니다.
- 잘못된 코드 입력은 사용자당 1시간에 10회로 제한합니다.

## 서버 (Supabase, 서울 리전)

- 테이블: `households`, `household_members`(계정↔집, 역할 OWNER/MEMBER), `invites`, 그리고 앱과 같은 구조의 `members`, `chore_definitions`, `week_plans`, `week_plan_targets`, `scheduled_chores`.
- 모든 테이블에 RLS를 적용합니다. 읽기는 같은 집 구성원만 가능하고, **쓰기는 RPC 함수로만** 합니다. 테이블에 쓰기 정책을 두지 않습니다.
- RPC: `create_household`, `create_invite`, `revoke_invites`, `join_household`, `push_changes`, `pull_changes`, `leave_household`, `delete_my_account`.
- `push_changes`는 행마다 앱이 마지막으로 본 서버 버전을 보냅니다. 같으면 저장하고 버전을 올리며, 다르면 충돌로 돌려주고 서버 행을 함께 보냅니다.
- 같은 주의 일정을 두 기기가 오프라인에서 따로 확정하면, 먼저 올린 쪽을 남기고 나중 쪽에는 "이미 있음"을 돌려줍니다.
- 앱에는 공개용 키(publishable key)만 넣습니다. service_role 키는 절대 넣지 않습니다.

## 앱 동기화

- SQLite 트리거가 공유 대상 테이블의 모든 변경을 `sync_outbox`에 기록합니다. 리포지토리 코드는 바꾸지 않습니다.
- 서버에서 받은 값을 적용하는 동안에는 `sync_mute` 표시로 트리거가 다시 기록하지 않습니다.
- 동기화 시점은 앱 시작, 앱 복귀, 데이터 변경 1.5초 뒤, 앱을 보는 동안 30초마다입니다. 실시간 연결(Realtime)은 쓰지 않습니다. 무료 플랜 동시 연결 200개 제한과 배터리를 고려했습니다.
- 순서: 올리기(부모 테이블부터) → 내리기(마지막 받은 시각 이후 바뀐 행) → 알림 재예약.
- 실패하면 다음 시점에 다시 시도하고, 화면에는 "마지막 동기화" 시각과 연결 상태를 보여 줍니다.

## 정책·법적 요건

| 요건 | 대응 |
|---|---|
| 수집 전 동의 (Apple 5.1.1(ii), 개인정보보호법) | 공유 시작 화면에서 항목·목적·보관·위탁·국외 이전을 보여 주고 동의 버튼 |
| 만 14세 미만 | 공유 시작·참여 전에 만 14세 이상 확인. 미만이면 공유 불가, 기기 안 기능만 사용 |
| 계정 삭제 (Apple 5.1.1(v), Play) | 설정 > 함께 쓰기 > "공유 그만두고 서버 데이터 삭제". 마지막 구성원이면 집 데이터 전체 삭제. 웹 안내 페이지(`docs/legal/account-deletion.html`) |
| 처리 위탁·국외 이전 | 수탁자 Supabase, Inc.(미국), 저장 위치 서울(AWS ap-northeast-2). 처리방침에 이전 항목·시기·방법·보유 기간·거부 방법 기재 |
| 보관 기간 | 탈퇴 시 즉시 삭제. 모든 구성원이 12개월간 접속하지 않으면 집 데이터 삭제. 구성원이 없는 익명 계정은 30일 뒤 삭제 |
| Play 데이터 보안 | 수집: 이름(별칭), 기타 사용자 콘텐츠(집안일·일정), 사용자 ID. 목적은 앱 기능. 공유 없음(서비스 제공자). 전송 중 암호화 예. 삭제 요청 가능 예 |
| App Store 개인정보 | 사용자와 연결된 데이터: 이름, 기타 사용자 콘텐츠, 사용자 ID. 앱 기능 목적, 추적 없음 |
