# 개인정보 설계

법률 자문이 아닌 개발 기준 정리입니다. 정식 처리방침은 출시 전 최종 코드 기준으로 작성하고, 개인정보보호위원회의 최신 「개인정보 처리방침 작성지침」 원문과 대조해야 합니다. 이번 조사에서는 해당 지침의 원문을 확인하지 못했고 2차 자료만 읽었습니다.

## 저장하는 것

| 데이터 | 위치 | 외부 전송 |
|---|---|---|
| 집 이름, 구성원 별칭, 비율 | 기기 SQLite | 없음 |
| 집안일, 일정, 완료 이력, 메모 | 기기 SQLite | 없음 |
| 앱 설정 | 기기 SQLite | 없음 |
| 백업 파일, 일정 공유 텍스트 | 사용자가 직접 선택한 곳 | 사용자가 공유할 때만 |

전화번호, 생년월일, 주소록, 위치, 사진, 마이크, 광고 ID를 받지 않습니다.

## 주의할 점

- 구성원 이름은 다른 사람의 정보일 수 있으므로 입력란에 "별칭으로도 충분해요"를 안내합니다. 메모에 민감한 내용을 쓰지 말라는 안내도 넣습니다.
- 로그에 이름과 일정 내용을 남기지 않습니다. 실기기 캡처는 `.device/`에 두고 커밋하지 않습니다.
- 저장소가 공개 상태입니다. 실제 이름이 담긴 스크린샷이나 테스트 데이터를 올리지 않습니다.

## 사용자 권리

- 설정에서 **모든 데이터 삭제**: DB와 예약 알림을 지우고 온보딩으로 돌아갑니다.
- **백업 내보내기·복원**: JSON 파일. 공유 전에 민감할 수 있다고 안내합니다.
- 계정이 없으므로 계정 삭제 기능은 해당 없습니다. 앱을 지우면 기기 안의 데이터도 함께 지워집니다. OS 자동 백업 대상에 포함될 수 있는지는 구현 때 확인합니다.

## 권한

| 권한 | 사용 |
|---|---|
| 알림 (`POST_NOTIFICATIONS`, iOS 알림) | 일정 알림. 첫 일정 확정 후 요청, 거부해도 동작 |
| `RECEIVE_BOOT_COMPLETED` | 재부팅 후 알림 복원. `expo-notifications` 포함 |
| 그 외 | 사용 안 함. `blockedPermissions`로 명시 차단 |

`SCHEDULE_EXACT_ALARM`, `USE_EXACT_ALARM`도 차단합니다. 빌드 후 병합된 매니페스트를 직접 확인합니다.

## 스토어 신고 초안

| 항목 | 답변 초안 |
|---|---|
| Google Play 데이터 보안 | 수집 없음, 공유 없음. 처리방침 링크는 필수. Google 기준 "수집"은 기기 밖으로 전송하는 것이고 기기 내 처리는 신고 대상이 아님. 사용자가 공유 시트로 보내는 동작의 취급은 제출 시 양식 설명 재확인 |
| Apple 앱 개인정보 | Data Not Collected |
| Apple 수출 규정 | `ITSAppUsesNonExemptEncryption: false` |

## 공유 모드를 켤 때 다시 할 일 (출시 후)

회원가입 항목, 만 14세 미만 처리, 국외 이전(Supabase) 고지, 앱 내 계정 삭제와 웹 삭제 페이지, RLS 시험, 스토어 신고 변경. 처리방침을 전면 개정해야 합니다.
